# 分镜台 · AI 剧本分镜助手

粘贴一段剧本，自动拆成可编辑、可导出的结构化分镜表。

> 关键判断：分镜表在这条链路里不是"文档"，是**接口**。它下游接着图生视频（首帧提示词 + 运镜 + 时长）和 TTS（台词 + 音色），所以每一列都必须能回答"谁在用、怎么用"。

## 快速开始

```bash
# 1. 配置模型 Key（任选一个）
cp .env.example .env
#    DEEPSEEK_API_KEY=sk-xxxx
#    或 ZHIPU_API_KEY=xxxx（open.bigmodel.cn，有免费额度）

# 2. 启动
node server.mjs
# 打开 http://127.0.0.1:7788
```

Windows 上双击 `start.cmd` 也行。

**没配 Key 也能打开**：自动载入内置示例结果，用于演示兜底。

## 它做了什么

```
剧本
 ├─ 第 1 步：抽取设定卡（人物 / 场景 / 道具）      → 一致性有了地基
 ├─ 第 2 步：带着设定卡逐场拆镜头                  → 结构化分镜 JSON
 └─ 第 3 步：规则引擎校准 + 冲突检测               → 可交付的分镜表
```

输出每一镜包含：镜号、景别、机位、构图、运镜、时长、画面内容、首帧提示词、角色、道具、台词（中/泰）、音色、音效、情绪。

## 三个设计决定

**1. 一致性靠"锚点注入"，不靠模型自觉**

角色卡里的外观锚点（发型、发色、服装、标志物）在拼首帧提示词时**原样保留，不许模型改写**：

```
【人物锚点，不可改动】周衍：黑色短发、深灰色衬衫、黑色长裤、肩宽、湿发贴额
【禁止出现】长发、西装外套、笑容
```

配合设定卡里的 `forbidden` 字段，生成后做冲突检测：描述里出现禁用词、角色挂了却没写进画面、道具声明了却没出现、连续三镜同景别 —— 全部标出来。

**2. LLM 和规则分工**

LLM 负责"看懂剧情、决定怎么切"；规则负责"守住视听语法"：

- 台词说不完 → 按 4.5 字/秒算，把时长拉到说得完为止
- 超出景别区间 → 收敛（特写 1.5–4s，全景 3.5–8s）
- 其余情况 → 尊重模型判断，不动

规则在 `public/rules.js`，纯函数，无 DOM 依赖，有 10 条单元测试。

**3. 字段按下游接口设计**

导出的 JSON 可以直接喂给图生视频和 TTS：`image_prompt` 是拼好的首帧提示词，`duration` 是模型时长参数，`dialogue[].line_th` 是泰语台词，`voice` 是音色档案。

## 文件结构

```
storyboard/
├─ server.mjs           零依赖 Node 代理（静态托管 + 调模型 + JSON 修复重试）
├─ prompts.mjs          两段式提示词模板
├─ public/
│  ├─ index.html        三栏工作台
│  ├─ styles.css        稿纸质感视觉系统
│  ├─ app.js            状态、渲染、导出
│  ├─ rules.js          规则引擎（纯函数）
│  └─ samples.js        内置示例剧本 + 离线兜底数据
└─ test/rules.test.mjs  单元测试
```

## 测试

```bash
node test/rules.test.mjs
```

## 换一个模型

只要对方兼容 OpenAI 的 `/chat/completions` 且支持 JSON 模式，改三个环境变量就行：

```bash
LLM_BASE_URL=https://api.siliconflow.cn/v1/chat/completions
LLM_API_KEY=sk-xxxx
LLM_MODEL=Qwen/Qwen2.5-72B-Instruct
```

内置支持：DeepSeek（默认）、智谱 GLM。

## 已知限制

- 单次剧本建议 6000 字以内，长剧本要分段（一致性靠设定卡，跨段需要把设定卡传下去）
- 配图只给提示词，没有真正出图
- 音色只做到"匹配 + 可确认"，没有接 TTS 出声
- 泰语台词由模型翻译，未做术语表校验
